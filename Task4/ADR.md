### <a name="_3bfxc9a45514"></a>**Функциональные требования**

**Use Cases**

**UC1**  
**Действующие лицо:** Сотрудники бэк-офиса депозитов и кредитов, АБС </br>
**Use Case:** Управление депозитными ставками </br>
**Описание:**

1. Сотрудник работает с депозитными ставками в АБС
2. Актуальные ставки становятся доступны Products Service
3. Products Service предоставляет ставки другим системам

**UC2**  
**Действующие лицо:** Менеджер кол-центра банка, система кол-центра, Products Service </br>
**Use Case:** Консультирование клиента по депозитным ставкам </br>
**Описание:**

1. Клиент обращается в кол-центр банка
2. Менеджер просматривает актуальные депозитные ставки в системе кол-центра
3. Система кол-центра получает ставки через Products Service
4. Менеджер консультирует клиента по условиям депозитов

**UC3**  
**Действующие лицо:** Products Service, партнёрский кол-центр </br>
**Use Case:** Передача депозитных ставок партнёру </br>
**Описание:**

1. Products Service получает актуальные депозитные ставки
2. Формируется файл с актуальными ставками
3. Файл передаётся в систему партнёрского кол-центра
4. Ставки становятся доступны сотрудникам партнёрского кол-центра

**UC4**  
**Действующие лицо:** Менеджер партнёрского кол-центра, система партнёрского кол-центра </br>
**Use Case:** Консультирование клиента по депозитным ставкам </br>
**Описание:**

1. Клиент обращается в партнёрский кол-центр
2. Менеджер получает информацию об актуальных ставках из системы партнёра
3. Менеджер консультирует клиента по условиям депозитов

### <a name="_qmphm5d6rvi3"></a>**Решение**

Существующая архитектура MVP сохраняется, расширяем только функциональность предоставления депозитных ставок

[Диаграмма контейнеров C4](./с4/container/to-be/to-be-container.puml))
[Диаграмма контекста C4](./с4/context/to-be/to-be-context.puml))

1. Используем существующую АБС для ведения депозитных ставок вместо создания отдельной системы управления ставками
2. Используем Products Service из предыдущего описания MVP для предоставления актуальных ставок другим системам
3. Избегаем прямых запросов кол-центров к АБС, чтобы не увеличивать нагрузку на её БД
4. Для интеграции внутреннего кол-центра с Products Service используем HTTPS / REST
5. Для партнёрского кол-центра реализуем файловую интеграцию, поскольку API-взаимодействие недоступно
6. В качестве механизма передачи файлов предлагаем SFTP
7. Экспорт ставок реализуем в рамках Products Service без создания дополнительного микросервиса
8. Используем Java / Spring Boot, поскольку в банке уже есть специалисты с опытом работы с Java

### <a name="_bjrr7veeh80c"></a>**Альтернативы**

1. Прямое получение ставок кол-центром из АБС
2. Создание отдельного Rates Export Service
3. Сохранение XLS-файлов как основного источника депозитных ставок
4. Использование REST API для передачи ставок партнёрскому кол-центру

**Недостатки, ограничения, риски**

1. Получение ставок из АБС может увеличить нагрузку на её БД, необходимо предусмотреть контролируемое обновление данных без постоянных обращений
2. При периодическом обновлении данных в Products Service ставки могут отличаться от актуальных значений в АБС
3. Файловая интеграция не гарантирует моментального обновления ставок в системе партнёрского кол-центра
4. Возможны сбои формирования, передачи или обработки файлов со ставками, необходимо предусмотреть контроль передачи
5. Банк не контролирует внутренние механизмы обработки полученных файлов партнёрским кол-центром
